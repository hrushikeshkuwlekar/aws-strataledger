[![Version: 1.2.0](https://img.shields.io/badge/version-1.2.0-emerald.svg)](https://github.com/hrushikeshkuwlekar/aws-strataledger)

**AWS StrataLedger** is an enterprise-grade, multi-account AWS inventory discovery and architecture visualization utility. Designed for modern multi-account AWS Organizations using **AWS IAM Identity Center (SSO)**, StrataLedger connects securely without long-lived IAM access keys, scans 90+ AWS resource types in parallel across accounts and regions, and generates an interactive, self-contained HTML report with authentic **AWS Reference Architecture landscapes** and security posture cards.

---

## 🌟 Key Features

- **🔐 100% AWS SSO / IAM Identity Center Native**: Reads `~/.aws/config` directly. Authenticates via temporary STS credentials generated by `aws sso login`. No IAM user credentials or hardcoded secrets.
- **🔇 Quiet Discovery by Default**: Zero console line spam or scrolling errors while running discovery. All discovery warnings, client errors, and framework logs are completely silenced so the Rich Progress bar renders smoothly. Only if `--verbose` (`-v`) is explicitly passed are detailed discovery logs and API timestamps printed.
- **🏛️ AWS Reference-Architecture Diagrams**: One diagram per account, drawn server-side as SVG with the **official AWS Architecture Icons** and AWS group conventions — AWS Cloud → Region → VPC, Availability Zones as columns and public / private / data subnet tiers as rows (tiers come from each subnet's real route table).
- **🧩 Parents Hold Their Children**: ALB/NLB → target groups, EKS → node groups & Fargate, Aurora / DocumentDB / Neptune → writer & readers, ElastiCache → cache nodes, ECS cluster → services, MSK, Amazon MQ, EFS, FSx, OpenSearch span exactly the AZs they run in. EC2 shows its EBS volumes and Elastic IPs.
- **📉 Readable at Any Scale**: Auto Scaling, EKS, Elastic Beanstalk and EMR instances collapse into one icon per subnet with a count; empty subnets and VPCs are summarised; only real relationships are drawn (Route 53 aliases, CloudFront origins, target groups, VPN, Transit Gateway, WAF, replication), routed around unrelated boxes.
- **🔍 Interactive Viewer**: Zoom, pan, fit, search, hover details, toggle connections, and export SVG/PNG — all offline.
- **🌓 Dark Mode & Light Mode**: Instant theme switching with `localStorage` persistence (diagrams stay on a white canvas, like AWS's own).
- **📊 Interactive Resource Metric Tiles**: Rich category metric cards replacing static progress bars with count and percentage share breakdowns.
- **🛡️ Per-Account Kubernetes & Firewall Metrics**: Dedicated columns for EKS Clusters, Subnet counts, and Active Firewalls (AWS Network Firewall + AWS WAF).
- **⚡ Concurrent Multi-Account & Multi-Region Engine**: ThreadPoolExecutor-based parallel scanning across accounts, regions, and service collectors with exponential backoff and rate-limiting resilience.
- **📋 90+ AWS Resource Types**: Comprehensive coverage across Compute, Networking, Storage, Databases, Application Integration, Analytics, Identity, Security, Edge and Monitoring.
- **📦 Self-Contained Deliverable**: Generates a single standalone HTML report with embedded CSS, JS, and SVG icons (zero server dependencies), plus structured JSON and CSV export.

## 📋 Prerequisites

Before installing AWS StrataLedger, ensure you have:

1. **Python 3.9 or higher**:
   ```bash
   python3 --version
   ```
2. **AWS CLI v2 installed**:
   ```bash
   aws --version
   ```
3. **AWS SSO Configured**:
   Your `~/.aws/config` must have at least one SSO profile configured (e.g. via `aws configure sso`).

### ⚠️ Ensuring the CLI is in your PATH

When installing with `--user` on macOS or Linux, pip places executable scripts in a user bin directory:
- **macOS (Python 3.9)**: `~/Library/Python/3.9/bin`
- **Linux**: `~/.local/bin`

If `aws-strataledger` is not recognized, add the directory to your `~/.zshrc` or `~/.bashrc`:

```bash
# For macOS (zsh)
echo 'export PATH="$HOME/Library/Python/3.9/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# For Linux (bash)
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

> **Tip**: You can always invoke the CLI directly using Python without modifying PATH:
> ```bash
> python3 -m aws_strataledger.cli --help
> ```

## ⚡ Quick Start Guide

### Step 1: Log in to your AWS SSO Profiles

Before running a scan, ensure your SSO session tokens are active:

```bash
# Log into your AWS SSO profile
aws sso login --profile prod
aws sso login --profile staging
```

### Step 2: Discover Available Profiles

Verify that StrataLedger can read your SSO profiles:

```bash
aws-strataledger profiles
```

*Output example:*
```text

┃ Profile  ┃ Account ID   ┃ Role          ┃ SSO Region       ┃ Default Rg ┃
┡━━━━━━━━━━╇━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━┩
│ prod     │ 123456789012 │ Administrator │ us-east-1        │ us-east-1  │
│ staging  │ 987654321098 │ Developer     │ us-east-1        │ us-west-2  │
└──────────┴──────────────┴───────────────┴──────────────────┴────────────┘
```

### Step 3: Run an Inventory Scan

Run a scan across one or more profiles and regions:

```bash
# Scan specific profiles and regions
aws-strataledger scan --profiles prod,staging --regions us-east-1,us-west-2

# Quick scan of single account and region
aws-strataledger scan --profiles prod --regions us-east-1

# Target specific domains (e.g. only compute and networking)
aws-strataledger scan --profiles prod --regions us-east-1 --services compute,networking

# Full multi-account organization scan (all profiles, all AWS regions)
aws-strataledger scan --profiles all --regions all
```

### Step 4: Open the Interactive Report

Once the scan completes, your artifacts are placed in `./reports/`:
- `scan-YYYYMMDD-HHMMSS.json` — Raw structured JSON inventory
- `report-YYYYMMDD-HHMMSS.html` — Standalone interactive visual report

Open the HTML file in any browser:

```bash
open ./reports/report-*.html   # macOS
xdg-open ./reports/report-*.html # Linux
```

## 📖 CLI Command Reference

### `aws-strataledger profiles`
Lists all detected SSO profiles from `~/.aws/config` along with their target AWS Account IDs, SSO roles, and regions.

```bash
aws-strataledger profiles
```

---

### `aws-strataledger scan`
Executes an inventory scan across specified accounts and regions.

```bash
aws-strataledger scan [OPTIONS]
```

| Option | Shorthand | Required | Default | Description |
|---|---|---|---|---|
| `--profiles` | `-p` | **Yes** | — | Comma-separated SSO profile names, or `all` |
| `--regions` | `-r` | **Yes** | — | Comma-separated AWS regions (e.g. `us-east-1,eu-west-1`), or `all` |
| `--services` | `-s` | No | `all` | Comma-separated categories: `compute`, `networking`, `storage`, `identity`, `security`, `monitoring` |
| `--output` | `-o` | No | `./reports` | Target directory for JSON and HTML output files |
| `--verbose` | `-v` | No | `false` | Enable verbose / debug logging |

---

### `aws-strataledger report`
Re-generates or customizes an HTML report from an existing JSON scan file without re-querying AWS APIs.

```bash
aws-strataledger report --input ./reports/scan-20261001-120000.json --output ./reports/custom-report.html
```

## 🔒 Recommended IAM Permissions

For security and compliance audits, AWS StrataLedger requires **read-only** permissions. We recommend attaching the AWS managed policy to your SSO Permission Set or Audit Role:

- `arn:aws:iam::aws:policy/ReadOnlyAccess`
- Or a custom policy combining service-specific `Describe*`, `Get*`, and `List*` actions.

StrataLedger performs **no write, update, or delete operations**.
